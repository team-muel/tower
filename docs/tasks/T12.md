# T12 — 프리셋 동료 위장 실종 + 진영 편향 생성

브랜치: `task/T12-preset-faction` / PR 제목: `T12: preset companions + faction-biased generation`
의존: T8·T11 (머지됨).

## 설계 근거 (캐논, 자체 포함)

- 로스터 = BG3 오리진 방식: **진영(1·2·3 플레이스홀더)마다 프리셋 동료 1명** + 무작위 생성 영입.
- **프리셋 위장 실종**: 프리셋 동료는 3사 실종제의 대상인 "척"한다 — 사망 카운트 3이면 실종 처리되어 사라지지만, **대회귀(3후퇴) 시 로스터에 다시 나타난다**. 생성형 동료의 실종만 영구. 이 규칙은 플레이어에게 숨긴다(UI에 차이 노출 금지).
- 생성형 동료: 진영 풀에서 생성 — 진영마다 성향·능력 태그 분포가 편향(예: 진영1=공격/소모 편향, 진영2=보호/부여, 진영3=기회/증폭).

## 산출물 (Tower.Core 순수 C# 위주)

1. `CharacterDef`(또는 상태)에 `isPreset` + `factionId` (1~3, 0=무소속). 기존 데이터 마이그레이션 최소화.
2. `ExpeditionRules` 확장: 실종 판정 시 프리셋은 `hiddenMissing` 상태(외부 조회는 실종과 동일하게 보임), **대회귀 시 hiddenMissing 프리셋은 로스터로 복귀**(사망 카운트 리셋 여부: 리셋 v0). 생성형은 기존대로 영구.
3. `CompanionGenerator` (Tower.Core): 시드 결정적 무작위 동료 생성 — 이름(간단 풀), 스탯 범위, 성향, 능력 2개를 **진영 편향 테이블**(진영별 성향/태그 가중치)에서 롤. 편향은 데이터 구조로 (하드코딩 분기 금지).
4. EditMode 테스트: 프리셋 위장 실종→대회귀 복귀, 생성형 영구 실종 유지(기존 테스트 불변), 생성 결정성(같은 시드=같은 동료), 진영 편향(대량 샘플에서 분포 차이 검증).
