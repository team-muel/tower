# T57 — Encounter outcome and provisional reward

**Branch** `task/T57-encounter-outcome-reward` · **PR title** `T57: record encounter outcomes and grant provisional rewards`

## Purpose

Record a resolved generated encounter into Run progress and grant exactly one
deterministic provisional reward per completed event, with a temporary result
banner. Economy detail is frozen; this lane ships data/interface seams only.

## Contract

- `GeneratedFloorEncounterHost` resolves with a structured
  `GeneratedEncounterResult` (event id, winning team, action count, duration)
  instead of a bare event id.
- `EncounterReward` is Core-pure and validated at creation (positive amount,
  non-None type, display name required).
- `RunRewardInventory` is the run-scoped ledger seam: one grant per event id,
  identical retries are idempotent (`false`), conflicting payloads for the same
  event are rejected. T58 owns serialization and lifecycle clearing.
- `EncounterRewardProfile` (ScriptableObject, data-authored `ER_Default`) maps
  ordinary encounters and the floor-10 Boss to separate reward entries.
  Provisional palette: ordinary = `Resource +1`, boss = `Ability +1`. Amounts
  and types are data, not code.
- `ForestFloorRenderer` validates the profile before scheduling encounters,
  and on victory: completes Run progress -> creates the reward -> grants it
  once -> presents the result. Failure at any step logs and stops; traversal
  unlock remains owned by the encounter host.
- `EncounterResultPresenter` is a provisional OnGUI banner (headline
  `VICTORY n/total`, reward + combat metrics detail, unscaled-time expiry).
  T60 owns final UI composition and styling.

## Explicitly out of scope

- Real economy values, drop tables, reward choice UI (frozen by owner ruling
  2026-07-10), defeat/retreat flow, multi-event Run lifecycle (T58), and final
  result UI (T60).
