# T52 — Encounter entry transition

**Branch** `task/T52-encounter-transition` · **PR title** `T52: encounter entry transition`

## Purpose

Make exploration-to-combat entry readable without turning combat into a turn
system: entering an enemy's encounter radius briefly holds player locomotion,
then restores direct control and starts the enemy's real-time brain.

## Contract

- Phase order is `Exploring -> IntroHold -> Active -> Resolved` and cannot
  retrigger.
- The intro hold is local to player locomotion. It does not set `Time.timeScale`,
  stop the world clock, or create a discrete combat turn.
- Hold timing consumes unscaled real time so Left Shift slow-mo cannot stretch or
  skip the entry beat.
- Enemy behaviour is disabled before engagement and becomes active only after
  the hold completes.
- Resolving or disabling the bridge must never leave player control locked.

## Initial integration

- The standalone CombatSpike uses a 7 m trigger and a 0.45 s hold before its
  pillbug brain becomes active.
- `EncounterTransition` is Core-pure so the generated floor/run presenter can
  reuse the same contract when node encounters are wired.

## Explicitly out of scope

- Global pause, turn scheduler restoration, encounter UI, rewards, waves, HP,
  generated-floor enemy spawning, and run event-count policy.
- T53 owns the deterministic 7–8 event/run plan; a later integration task maps
  generated node encounters to this transition.

## Verification

- EditMode tests cover threshold entry, hold duration, frame-rate independence,

- Full EditMode gate and CombatSpike Windows64 build pass.
- Desktop executable is used to verify the player can approach the enemy, is
