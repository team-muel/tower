# T67 — package β: commander stance and precise bullet-time orders

**Branch** `task/T67-command-package-beta` · **PR title** `T67: package beta command loop`

## Owner decision

2026-07-21: the owner selected package β ("commander") from D1:

- companions keep an always-on command stance: Assault, Guard, or Focus;
- Left Shift bullet-time is the only window for one-shot precise orders;
- slow-mo charge uses time-based passive recharge only;
- tags remain a no-timing-window real-time rule;
- companion intent telegraphs and disposition labels are always readable.

## Implementation

- `RealtimeCommandBoard` is Core-pure and keeps stance assignments plus expiring
  precise orders deterministic.
- `ActionScorer` applies command stance weights on top of personality weights and
  can produce a forced ability/target plan.
- `AutonomousCombatDriver` exposes a 0.75-second intent telegraph, consumes a
  precise order on successful execution, and falls back to autonomous behavior
  when a target becomes invalid.
- Generated encounters expose stance and precise-order seams. The run surface
  binds `F1-F3` selection, `1/2/3` stance controls, and `Q` precise order while
  Left Shift is held.
- World views display disposition and the current intended action.

## Verification gate

- Core/EditMode tests must cover stance defaults, stance scoring, focus target
  bias, command-window rejection, precise-order expiry/replacement, forced
  target execution, fallback after stale targets, and 0.75-second telegraph
  timing.
- Unity EditMode and the generated-floor desktop flow remain the final gate.
