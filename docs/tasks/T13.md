# T13 — 인게임 QA 하니스 + 카메라 튜닝 모드

브랜치: `task/T13-qa-harness` / PR 제목: `T13: QA harness + camera tuning mode`
의존: T10 (머지됨). 배경: Win32 클릭 주입 QA 기각(사용자, 2026-07-06) — 게임 상태를 구조적으로 조회·조작할 채널 필요. + 카메라 구체값은 인게임 튜닝으로 확정하는 프로세스 채택(31 §2).

## A. QA 채널 (dev 전용)

`-qaPort <n>` 커맨드라인 인자가 있을 때만 활성 (인자 없으면 코드 경로 완전 비활성). TCP 라인 프로토콜 (localhost 전용):
- `press <buttonName>` — 활성 씬의 uGUI Button을 GameObject 이름으로 찾아 onClick invoke. 결과 `OK`/`ERR <이유>`.
- `state` — JSON 한 줄: 현재 씬 이름, (전투 중이면) 라운드·이니셔티브 큐·유닛별 HP/위치/마크, (원정 중이면) 층/방/전진·후퇴 카운트.
- `scene <name>` — 씬 로드. `quit` — 종료.
- 구현: 명시적 레지스트리(상태 공급자·버튼은 등록된 것만 노출 — 리플렉션 전역 스캔 금지). 파서·직렬화는 Tower.Core 순수 C#(테스트 대상), TCP·Unity 배선은 Tower.Combat.

## B. 카메라 튜닝 모드 (dev 전용)

`-devcam` 인자 시 활성: 런타임 카메라 리그에 조정 키(pitch I/K, 거리 +/-, FOV [/]) + 좌상단에 현재 값 텍스트 표시 + `P`로 현재 값 JSON을 `%TEMP%\tower-cam.json`에 덤프. v0 기본값 적용: pitch 52°, 줌 범위 8~20m, 기본 14m, FOV 38, 추적 감쇠 0.12s. 유저 스크롤 줌은 상시(비-dev에서도) 활성.

## C. AltTester 등 외부 도구 평가 (조사만, PR 본문에 기록)

AltTester Unity SDK(무료 티어·Unity 6 호환), Airtest+Poco, GameDriver(상용이면 기각), Unity AssistiveSupport(접근성용 — 부적합 예상). 웹 조사 30분 내. **자체 하니스(A)는 평가 결과와 무관하게 구현** — 외부 도구가 좋아도 A는 에이전트 파이프라인의 최소 보장.

## 산출물·게이트

EditMode 테스트: 명령 파서, state 직렬화(고정 시나리오), 레지스트리 규칙. 카메라 튜닝은 값 클램프 로직 테스트. 이 태스크는 워크트리에서 코드+테스트만 작성 가능 — dev 빌드 TCP 실검증은 오케스트레이터가 수확 시 수행.

## 규약 리마인드
