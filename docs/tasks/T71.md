# T71 — live combat state on the QA channel

**Branch** `task/T71-live-combat-qa-state` · **PR title** `T71: expose live combat QA state`

The generated-floor fight already runs the package-β command loop and T70 hit
feedback, but the existing `-qaPort state` response only described the older
turn-based DTO shape. T71 closes that observability gap without adding a new
gameplay rule or changing the simulation authority.

## Implementation

- `ForestFloorRenderer` registers one explicit QA state contributor while the
  dev harness is enabled. It reports run floor/node, encounter phase, pending
  event, retreat/conquest state, and the last resolved outcome.
- `GeneratedFloorEncounterHost` projects the live Core state into the QA DTO:
  HP/alive/team/position/marks, disposition, current telegraph, target,
  stance, encounter lifecycle, and active damage popups.
- Command telemetry and pending precise orders are serialized in deterministic
  unit/order order, so a harness can verify issue → telegraph → resolve,
  fallback, expiry, and visible HP change from `state` polls.
- The existing turn-oriented fields remain in the contract for older harness
  consumers; real-time truth is carried by `elapsedSeconds`, lifecycle flags,
  `intents`, and `preciseOrders`.
