# T46 — PlayerIsoController → Animator wiring

**Branch** `task/T46-player-animator` · **PR title** `T46: drive player Animator from locomotion`
**Assemblies** `Tower.Core` (pure helper + tests) and `Assets/Gameplay` (Assembly-CSharp)

## Why

`Prototype.unity` is the sole build scene. Its player is the **Blink FREE Low Poly Human**
(`HumanMale_Character_FREE`, valid Humanoid Avatar, `LowPolyHumanAnimator` controller,
32 combat/locomotion clips). `PlayerIsoController` moves the transform but **never touches
the Animator**, so the character T-poses/idles while sliding across the forest.

Smallest change with the largest sensory payoff: feed planar speed into the Animator.

## v0 rules (do NOT decide these yourself)

1. **Pure logic goes in `Tower.Core`**, not in the MonoBehaviour (AGENTS.md #3, and the
   test assembly cannot reference `Assembly-CSharp`). Add:
   ```csharp
   namespace Tower.Core
   {
       public static class PlayerLocomotion
       {
           // planar (XZ) speed in m/s, ignoring vertical ground snapping
           public static float PlanarSpeed(Vector3 previous, Vector3 current, float deltaTime);
           // 0..1 normalized against the controller's max speed
           public static float SpeedFactor(float planarSpeed, float moveSpeed);
       }
   }
   ```
   `Vector3` here is `UnityEngine.Vector3` — `Tower.Core` already references UnityEngine.
   Guard `deltaTime <= 0` → return 0. Guard `moveSpeed <= 0` → return 0.
   `SpeedFactor` clamps to `[0,1]`.

2. **Do not invent Animator parameter names.** Open
   `Assets/Blink/.../LowPolyHumanAnimator.controller` **as a text/YAML file** and read the
   real parameter names and states. Do **not** launch the Unity editor. Record what you
   found in the PR body. If a float parameter for speed does not exist, expose
   `[SerializeField] string speedParameter = "Speed";` and no-op safely when absent
   (see rule 3).

3. **Fail soft, never throw.** At `Start()`:
   - `if (animator == null) animator = GetComponentInChildren<Animator>();`
   - cache `Animator.StringToHash(speedParameter)`
   - verify the parameter exists via `animator.parameters` (type `Float`); if not,
     log **one** `Debug.LogWarning` and disable animator driving for the rest of the run.
   Never call `SetFloat` on a controller that lacks the parameter — Unity spams the console.

4. **Do not change movement, ground snapping, camera, or the Rigidbody.** The controller
   drives the transform; the Rigidbody stays `isKinematic = true, useGravity = false`
   (a non-kinematic tall character tips over).

5. **Do not edit scenes and do not open the Unity editor.** You work in a `git worktree`.
   Inspector assignment is the orchestrator's job after merge. Do not create `.meta` files.

### 2. `Assets/Gameplay/PlayerIsoController.cs` (edit)

```csharp
[Header("Animation")]
[SerializeField] private Animator animator;
[SerializeField] private string speedParameter = "Speed";
[SerializeField] private bool normalizeSpeed = true;   // send 0..1 instead of m/s
[SerializeField, Min(0f)] private float speedDamping = 0.12f;  // SetFloat damping time
```

At the **end** of `Update()` (after `transform.position = pos;`, currently line ~71):

```csharp
if (_animatorReady)
{
    float planar = PlayerLocomotion.PlanarSpeed(_prevPos, transform.position, Time.deltaTime);
    float value  = normalizeSpeed ? PlayerLocomotion.SpeedFactor(planar, moveSpeed) : planar;
    animator.SetFloat(_speedHash, value, speedDamping, Time.deltaTime);
}
_prevPos = transform.position;
```

Measure speed from **actual travelled distance**, not from the input vector — ground
snapping and collisions mean the two differ, and the feet will slide if you use input.

### 3. Tests — `Assets/_Tower/Tests/EditMode/PlayerLocomotionTests.cs`

- `PlanarSpeed` ignores the Y delta (a pure vertical move on a slope → speed 0).
- `PlanarSpeed(deltaTime: 0)` → `0` (no divide-by-zero).
- `SpeedFactor` clamps: over-speed → `1`, negative → `0`, `moveSpeed = 0` → `0`.
- `SpeedFactor(moveSpeed, moveSpeed)` → `1` within `1e-4`.
