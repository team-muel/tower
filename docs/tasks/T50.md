# T50 — Autonomous combat driver v0 (1v1 Core spike)

**Branch** `task/T50-autobattle-driver-core` · **PR title** `T50: autonomous combat driver core`

## Purpose

Prove the current combat substrate can form a readable, deterministic 1v1
autonomous encounter:

`CombatState -> ActionScorer -> bounded analog movement -> AbilityResolver`

This is the next risk called out by `13 Combat Model v0.1` §8.5. It is not a
replacement turn scheduler and does not decide the open player-preview question
in `00 Current Status.md` A0.

## In scope

- Add a scene-free `Tower.Core` driver with caller-provided fixed tick duration
  and movement speed. It must not hide gameplay tuning in a constant.
- Each accepted tick advances `CombatState.ElapsedSeconds`, then evaluates every
  living combatant once in stable `LivingUnitIds` registration order.
- For each selected `AiPlan`, clamp movement to `speed * tick duration` and
  move through `IBattlefield`. An ability resolves only after the planned
  reposition has actually been reached; partial movement never grants a
  projected-range attack.
- Resolve abilities through `IAbilityExecutor`, retain normal combat-end
  behavior, and return a test-visible per-unit tick trace.
- Add EditMode coverage for elapsed time, bounded movement, deferred ability
  resolution, deterministic repeated simulation, and combat completion.

## Deliberately not decided here

- **A0 owner preview:** real-time permanence versus a turn fallback; no
  decision is encoded by this task.
- **Speed / initiative:** the current `CharacterDef.Speed` has no real-time
  cadence contract. T50 uses a uniform caller-provided fixed tick only; it does
  not make speed a cadence rule.
- **Cooldown migration:** `AbilityDef.cooldownRounds` and
  `CharacterState.WithCooldownsTicked()` still describe deleted round
  semantics. T50's proof fixture uses zero-cooldown abilities and must not
  invent a rounds-to-seconds conversion. A follow-up owns that data migration.
- Unity scene wiring, body animation, player control, Left Shift command mode,
  slow-mo, counter results, HP presentation, encounters/waves, and authored
  enemy data.

## Dependency order after T50

1. **Owner:** preview `_CombatSpike.unity` and close A0. This does not block
   the Core proof, but it gates command/counter product decisions.
2. **T50:** Core 1v1 autonomous driver (this task).
3. **T51:** specify and migrate real-time cadence plus cooldown seconds,
   including how `CharacterDef.Speed` affects action frequency.
4. **T52:** visual 1v1 host that maps the T50 driver to real bodies and
   readable telegraphs. Depends on T50 and T51.
5. **T53:** player direct control plus Left Shift party-command window and the
   counter relationship. Depends on the A0 decision and T52.
6. **T54:** data-authored enemy/ally sources and EncounterBudget/Composer
   integration. Depends on T51/T52; the EncounterBudget API is unchanged.
