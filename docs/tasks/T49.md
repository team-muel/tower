# T49 — Demolition: remove the grid, the turn scheduler, encounter execution, and Tower.UI

**Branch** `task/T49-demolition` · **PR title** `T49: demolition (grid, turn scheduler, encounters, UI)`
**This is a single serial task.** Do not split it — the deletions interlock.

## Why

The project pivoted (vault 18/38): combat becomes **real-time telegraph -> space-bar slow-mo ->
multiple-answer counter**, and the sole build scene is the walkable 3D forest
(`Prototype.unity`). The old vertical slice — BG3-style **grid** + **turn scheduler** + scene
sequence UI (Boot -> Camp -> Loadout -> Expedition) — is code-complete, tested, and **unreachable
from the build**. Two half-games. The owner chose to demolish the dead half.

T49 clears the ground. T48 (slow-mo combat) builds on it.

## The one thing that is NOT a deletion

`TurnEngine` is **not** a scheduler bolted onto combat. It is the **combat state container**:
it owns units, HP, cooldowns, round number. All of these take it as a parameter:

- `AbilityResolver.Execute(TurnEngine, UseAbilityCommand)`
- `ActionScorer.ChooseAction(TurnEngine, unitId)`
- `ICombatObserver.OnCombatStarted/OnRoundStarted/OnCommandCommitted(TurnEngine, ...)`
- `IAbilityExecutor.Execute(TurnEngine, ...)`
- `CombatMetrics.*(TurnEngine, ...)`

The owner wants abilities, the order board, and the disposition AI **kept**. Therefore:

> **Extract `CombatState` out of `TurnEngine`. Keep the state. Delete the turn loop.**

`CombatState` (new, `Tower.Core`) holds: registered combatants, HP, cooldowns, the status-board
hook, and an `ElapsedSeconds` notion instead of `RoundNumber`. Everything that used to take
`TurnEngine` now takes `CombatState`. Where a call site only needed `RoundNumber` to expire
statuses, give `StatusBoard` an explicit prune-by-elapsed-time entry point and say so in the PR.

If the extraction turns out to be bigger than deleting and rewriting `AbilityResolver`, **stop and
report**. Do not silently rewrite the ability pipeline.

## Traps

1. **Move the `.meta` with the `.cs`.** Losing the GUID silently detaches
   `FloorGraphTerrainPreview` from `Prototype.unity` and the terrain preview vanishes.
2. Batchmode Unity needs `ALLUSERSPROFILE`, `ProgramData`, **and** `TMP` set, or UPM IPC dies
   with `Failed to start the Unity Package Manager local server` (exit 1, no result XML,
   zero `error CS` — very easy to misdiagnose). Do **not** pass `-quit` with `-runTests`.
3. `Assets/Settings/*_RPAsset.asset` get dirtied by the editor. `git checkout --` them before
   committing.
4. When this brief says "no X anywhere", it means **in code**, not in comments.
5. `git -C C:\dev\tower-wt-T49 ...` — never `cd` then `git`. Commit with `-c commit.gpgsign=false`.
