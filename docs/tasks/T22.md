# T22 — 전투 주스 프레젠터 (Combat Feel / Juice)

/ 근거: 설계 vault `40 Synthesis §2` (사용자 진단 "실전감각 부족"). 이 태스크는 규칙이 아니라 **피드백의 즉각성**을 만든다. 코드만으로, 아트 0원으로, Core 무변경으로 "원시적"을 "경쾌"로 바꾸는 것이 목표.

## 배경 (자체 포함)

- 전투 로직은 이미 아날로그(연속) 전장에서 돈다(T20~T21 + fix/analog-movement). 유닛은 이제 연속 위치로 부드럽게 활강한다.
- 없는 것: **타격 피드백.** 데미지가 조용히 숫자만 바뀐다. 그래서 "경쾌한 BG3 전투"가 안 느껴진다.
- Core는 이미 무슨 일이 일어났는지 이벤트로 뱉는다: `Tower.Core/TurnPresentationEvent.cs`, `ICombatObserver.cs`, `CombatDamageEvent.cs`. **이 이벤트를 Combat/UI 층에서 구독해 반응만 붙인다.**

## v0 규칙 (작업자가 임의로 바꾸지 말 것)

1. **Core 무변경.** `Tower.Core` asmdef의 게임 로직/시그니처를 바꾸지 않는다. Physics 참조 금지, 전역 `Time.timeScale` 금지. 필요한 이벤트가 이미 없다면 관찰(observer) 콜백 데이터만 최소 확장하되, 결정성·QA state·시뮬 결과에 영향 0을 증명할 것.
2. **연출은 프레젠터 로컬 시간으로.** 히트스톱은 `Time.timeScale`이 아니라 프레젠터 로컬 스케일/코루틴으로 (T19 지휘모드가 쓰는 "프레젠터 로컬 0.25x" 기법 재사용). 시뮬/QA/결정성 불변.
3. **외부 패키지 추가 금지.** DOTween 등 도입 금지 — 트윈/이징은 자체 코루틴으로. (manifest 변경 금지. com.coplaydev.unity-mcp 라인은 건드리지 말 것 — 별도 작업 중.)
4. **하드코딩 금지.** 연출 파라미터는 데이터로. 아래 `AbilityFeelDef` 참조.

## 산출물

1. **`AbilityFeelDef`** (데이터 — `Tower.Core` 또는 `Tower.Combat` 중 결정성 안전한 쪽; 순수 데이터라면 Core 허용):
   - `hitstopMs` (int), `shakeIntensity` (float), `popupStyle` (enum: Normal/Crit/Consume/Heal), `approachTween` (enum: None/Lunge/Projectile), `sfxCue` (string, 이번엔 배선만 비워둠 — T24에서 사용).
   - `AbilityDef`에 옵셔널 `feel` 참조를 달거나 별도 룩업. 기존 능력에 기본값 제공(널이면 Normal 프로필).
2. **전투 주스 프레젠터** (`Tower.Combat` 또는 `Tower.UI`, MonoBehaviour):
   - `TurnPresentationEvent`/`ICombatObserver`/`CombatDamageEvent` 구독.
   - (a) **히트스톱**: 타격 순간 60~120ms 프레젠터 로컬 정지.
   - (b) **대미지 팝업**: 피격 위치에 TMP 숫자 튀어오름+페이드. Crit/Consume는 크게/색 다르게.
   - (c) **셰이크**: 카메라(OrbitCameraRig) 또는 피격 토큰의 짧은 위치 노이즈, `shakeIntensity` 차등.
   - (d) **공격 트윈**: 근접=대상 쪽 lunge 후 복귀, 원거리=투사체 대용 라인 트윈. `UnitToken`에 연출 훅 추가(로직 위치는 이미 battlefield가 정본이므로 시각만).
   - (e) **텔레그래프**: 유닛의 `PendingAbility`(이미 존재)를 행동 전에 대상/자신 위에 예고 마커로.
   - (f) **소모(마크 폭발) 강조**: 태그 `소모` 발동 시 팝업/셰이크를 가장 크게 — 연계의 시그니처 순간.
3. **PlayableExpeditionController 배선**: 프레젠터를 전투 셋업 시 생성/구독 연결. 기존 흐름(analogController, SyncTokensToBattlefield) 깨지 않게.
4. **EditMode 테스트**: 순수 매핑 로직(이벤트→feel 파라미터 resolver, `AbilityFeelDef` 기본값/조회)을 단위 테스트. MonoBehaviour 시각 자체는 테스트 불가하나 **데이터·매핑은 반드시 테스트**. 기존 344 전부 유지.
