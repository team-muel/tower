# T1 — 코어 데이터 모델

브랜치: `task/T1-data-model` / PR 제목: `T1: core data model`
의존: T0 (머지됨). 설계 근거: vault `13 Combat Model v0.1.md` §1·§4·§5 (레포 밖 — 요지는 아래에 자체 포함).

## 목표

전투·편성의 데이터 어휘를 ScriptableObject + 순수 C# 규칙으로 세운다. **씬·UI·MonoBehaviour 없음.** 모든 규칙 로직은 Tower.Core의 순수 클래스로 (유닛 테스트 대상).

## 설계 요지 (자체 포함)

- 동료는 직접 조작 불가, 고유 성향 AI. 회귀자만 수동. 능력에 태그: 부여(마크 적용)/소모(마크 폭발)/증폭(배율).
- 능력 슬롯: 인물당 시작 2, 범위 1~4 (게임 중 증감).
- 속도 스탯 = 개별 이니셔티브 순서. 플레이어가 튜닝 가능(방식 미정 — 데이터만 준비).
- 사망 카운트 존재 (3사 실종제 — 규칙 자체는 T8 범위, 필드만).

## 산출물 (Assets/_Tower/Scripts/Core + Data)

1. `AbilityTag` enum: None/Apply/Consume/Amplify. `DispositionType` enum: Aggressive/Protective (확장 전제 — switch 증식 금지).
2. ScriptableObject 정의:
   - `MarkDef`: id, 표시명, 지속(턴), 스택 가능 여부.
   - `AbilityDef`: id, 표시명, tag(AbilityTag), 대상 마크(MarkDef, Apply/Consume용), 사거리, 코스트, 기본 위력, 증폭 배율(Amplify용), 대상 유형(적/아군/셀).
   - `PassiveDef`: id, 표시명, 효과 훅 식별자(문자열 키 — 구현은 후속 태스크).
   - `CharacterDef`: id, 표시명, 최대HP, 공격, 방어, 속도, 성향(DispositionType), 패시브(PassiveDef), 기본 능력 목록(AbilityDef[]), 회귀자 여부(bool).
3. 순수 C# 런타임 상태 (SO와 분리): `CharacterState` (currentHp, deathCount, 할당 능력 리스트, 속도 보정), `AbilityLoadout` — **슬롯 규칙 강제: 1~4, 기본 2** (초과/미달 시 명시적 실패 반환, 예외 아닌 Result 패턴).
4. 슬라이스 콘텐츠 데이터 에셋 생성 (Data/ 폴더, .asset): 마크 2종(예: 빙결·화상), 능력 10종(부여3/소모3/증폭2/무태그2), 인물 4(회귀자+동료3: Aggressive×2, Protective×1), 패시브 3. 이름·수치는 임시값 — 밸런스 무관, 태그 조합 커버가 목적.
5. EditMode 테스트: 슬롯 규칙(1~4 경계), 에셋 무결성 테스트(모든 AbilityDef의 tag별 필수 필드 채워짐 — Apply/Consume엔 markDef 필수 등).
