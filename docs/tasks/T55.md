# T55 — Real-time combat cadence

**Branch** `task/T55-realtime-cadence` · **PR title** `T55: migrate combat cadence to real time`

## Purpose

Replace the deleted round scheduler's remaining timing assumptions with an
explicit real-time contract before the autonomous combat driver is connected
to the generated encounter host.

## Contract

- Speed 10 is the authored baseline and acts once per second.
- A unit's action interval is `10 / max(1, EffectiveSpeed)` seconds.
- Every fixed simulation tick emits at most one action per living unit; units
  keep independent next-action timestamps in deterministic registration order.
- Ability cooldowns, mark durations, and amplify duration use elapsed seconds.
- Existing authored round values migrate 1:1 to seconds because the prior
  baseline cadence was one action round per second-equivalent step.
- Cooldowns advance continuously with `CombatState.ElapsedSeconds`; non-finite
  and negative values are rejected.

## Explicitly out of scope

- Scene/host wiring, HP presentation, player orders, rewards, waves, and Run
  lifecycle. T56 owns generated-encounter runtime wiring and combat resolution.

## Verification

- EditMode tests cover speed-to-interval mapping, independent fast/slow unit
  cadence, fractional cooldown advance/expiry, elapsed status expiry, data
  schema loading, and authored asset integrity.
- Full EditMode and a Windows64 build are required before completion.

- Full EditMode: **451/451 passed**, 0 failed, 0 skipped.
- CombatSpike Windows64: **Succeeded**, Errors=0, Warnings=0.
- The driver now schedules the authored slice speeds independently: speed 20
