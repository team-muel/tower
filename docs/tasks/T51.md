# T51 — Companion entities v0

**Branch** `task/T51-companion-entities` · **PR title** `T51: companion entities`

## Purpose

Turn the existing companion definitions into actual in-world party members.
The previous target animatic overreached into command-point and skill-tag UI;
the owner corrected the next dependency on 2026-07-13: make the companion
entities first and follow the local character references faithfully.

Reference contract:

- `31 Visual Design Prep` §1a: player uses the Blink human; companions use the
  ithappy modular humanoid substrate, with silhouette/palette variation and a
  minimal idle/walk animation contract.
- `78 Character Asset Pipeline`: the free asset-store humanoids replace the
  abandoned AI-3D composite route; one normalized humanoid contract is shared
  by roster members.
- `13 Combat Model v0.1` §8: party members are autonomous entities backed by
  the same `CharacterDef`/combat data as the rest of the simulation.

## In scope

- Add a data-driven `CompanionVisualProfile` that binds one `CharacterDef` to
  a modular body prefab, locomotion controller, palette accent, formation
  offset, and movement tuning.
- Add an in-world `CompanionEntity` with stable identity, kinematic physics,
  locomotion animation, formation following, enemy facing, and material tint.
- Add a reusable `CompanionPartySpawner` with validation for duplicate or
  invalid roster entries.
- Build three modular ithappy companion prefabs and profiles for the existing
  Ember Vanguard, Ward Bearer, and Glass Breaker definitions.
- Mark those three definitions as the v0 faction presets (factions 1/2/3).
- Replace the T48 spike's anonymous noop companion body with those three real
  entities and register their real definitions/loadouts in `CombatState`.
- Preserve the existing Blink player, pillbug telegraph, and Left Shift slow-mo
  reference lane.

## Explicitly out of scope

- Command UI, movement-point selection, ability/tag-intent UI, skill-slot UI.
- Multi-answer counter design or presentation.
- Real-time `Speed` cadence and `cooldownRounds -> seconds` migration.
- Ability execution, HP/damage view mapping, waves, progression, economy, or
  generated infinite-roster visual rolling.

The T50 note's old “T51 = cadence/cooldown” ordering is superseded by the
owner's dependency correction above. Cadence/cooldown remains open after the
entity substrate; it is not silently decided here.

## Verification

- EditMode coverage proves profile validation, identity binding, deterministic
  formation targets, distinct party spawning, and kinematic body setup.
- Full EditMode gate passes with zero C# compile errors.
- Rebuild the standalone CombatSpike Windows64 preview and verify three
  distinct humanoid companions are visible in the desktop executable without
  command/counter UI additions.
