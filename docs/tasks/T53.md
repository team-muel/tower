# T53 — Run event plan

**Branch** `task/T53-run-event-plan` · **PR title** `T53: deterministic run event plan`

## Purpose

Give each fresh ten-floor stair-step a deterministic, saveable sequence of
seven or eight combat events without inventing reward, economy, or narrative
event types before their owner lanes.

## Contract

- A run contains exactly ten floors and seven or eight events.
- The last event is always the floor-ten boss.
- The preceding six or seven events are ordinary encounters on unique floors
  from one through nine, ordered by traversal.
- A seed reproduces the same layout; different entry seeds can produce a
  different event count and floor selection.
- Progress is an ordered prefix. Repeating a completed event is idempotent;
  skipping an unresolved event is rejected.
- Save data includes the generated slots as well as the seed and completion
  prefix, so an in-progress run is stable even if generation changes later.

## Explicitly out of scope

- Encounter composition, rewards, economy, narrative events, map spawning,
  combat resolution, and Run advance/retreat/grand-regression rules.
- T54 maps these slots to generated-floor encounter nodes and the T52 entry
  transition.

## Verification

- EditMode tests cover the 7/8 bounds, both count outcomes across seeds,
  uniqueness/order, mandatory final boss, deterministic generation, layout
  variation, ordered/idempotent completion, invalid snapshot rejection, and
  repository JSON round-trip.
