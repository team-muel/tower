# T23 — 이니셔티브 리본 가독성 (Turn Order Readability)

/ 근거: 설계 vault `40 Synthesis §2.3 #6`. 대인원 파티(11 §5)에서 "지금 누구 차례이고 다음이 누구인지"의 즉각적 가독성이 페이싱의 생명줄. 텔레그래프(펜딩 능력 예고)는 T22에서 이미 구현됨 — **T23은 순서 리본만** 다룬다.

## 배경 (자체 포함)

- 행동 순서 체인(T21)과 `TurnOrderSlot`(Tower.UI), 이니셔티브 병합 정렬이 이미 있다.
- 전투 HUD에 이니셔티브/순서 표시는 있으나 정적이다. 현재/다음 행동자가 시각적으로 두드러지지 않고, 턴 이양이 즉각적으로 읽히지 않는다.

## v0 규칙 (바꾸지 말 것)

1. **Core 무변경.** Tower.Core 로직/시그니처 불변. 순서 데이터는 기존 TurnEngine/CurrentRoundOrder/CurrentTurn에서 읽기만. Time.timeScale·Physics 금지.
2. **외부 패키지 추가 금지.** manifest 변경 금지(특히 com.coplaydev.unity-mcp 라인 유지).
3. **결정성·QA state 불변.** 리본은 순수 표시. 시뮬/결정성 테스트 영향 0.
4. **T22 프레젠터와 충돌 금지.** T22가 만든 주스 프레젠터/텔레그래프를 건드리지 말 것(리본은 별개 UI 컴포넌트).

## 산출물

1. **이니셔티브 리본 UI** (Tower.UI): 라운드 순서를 가로 리본으로 표시(아군/적 색 구분, 아바타/이니셜/색 토큰). 현재 행동자 = 강조(펄스/확대/테두리), 다음 행동자 = 약한 강조. 턴 이양 시 리본이 슬라이드/시프트되어 다음 유닛이 선두로. 사망 유닛은 리본에서 제거/흐림.
2. **데이터 소스**: `TurnEngine.CurrentRoundOrder` + `CurrentTurn.UnitId` + 생존 여부(IsAlive) + 팀(CombatTeam). 아군 체인 순서(T21) 반영.
3. **PlayableExpeditionController 배선**: 전투 셋업 시 리본 생성/갱신 구독(턴 변경마다 refresh). 기존 HUD 레이아웃(엣지 HUD, 3D 뷰포트 비우기 원칙 — 00 참조)과 겹치지 않게 상단/하단 엣지 배치.
4. **EditMode 테스트**: 순수 표시 로직(순서→리본 항목 매핑: 현재/다음 플래그, 사망 필터, 팀 분류)을 단위 테스트. 기존 테스트 전부 green(현재 350).
